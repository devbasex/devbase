# #273: 決定の記録・テスト設計・未確認のまま残ること

`issues/issue-273-design.md`（設計の本体）の続きである。不変条件（I1〜I11）・機能（F1〜F9）・イベント（E1〜E11）の
番号は本体のものを指す。

## 決定の記録

### 決定 1: #268 はこの課題の設計で直す

#268 の 2 つの原因（`sync` がチーム共通だけへ書く・控えの登録がチーム共通だけを見る）は、#273 の
「CLI と TUI の書き込み先の決め方を揃える」と同じ規則（前提 4・5）で解ける。別に保つと、TUI から `sync` を
選んだ利用者が #268 の不具合をそのまま踏み、同じ `cmd_env_sync` を 2 回に分けて書き換えることになる。
#268 を閉じるかは依頼者が決める（未確認のまま残ること）。PR の本文では番号を挙げるだけにする。

### 決定 2: 控えに登録の無いソースは、知らせたうえで今のファイルと値を比べて同期する

知らせるだけにすると、#268 の端末は `sync` を何度打っても更新されず、`init --reset` しか道が無い。
今のハッシュで登録だけすると、次の `sync` が「変更なし」と判定し、古い値が残り続ける。値の比較なら
ハッシュが無くても正しく判定でき、比べた後に登録すれば以後はハッシュで検出できる。

### 決定 3: `sync` の 2 つの参照の保存は順に行い、原子的にしない

OpenBao の KV v2 は参照をまたぐトランザクションを持たない。個人共通を先に保存するのは、#268 の対象
（個人の認証情報）を先に直すためである。片方だけ保存された状態は、次の `sync` がハッシュの控えを
更新していないため同じ変更を再び検出して書き直す（控えの更新は保存の後に行う）。

### 決定 4: TUI の一覧は `cmd_env list` の出力ではなく、行を返す関数から作る

行を選んで編集するには、キーと参照の組を構造として持つ必要がある。`list` の出力を読み取ると表示の文言が
契約になり、`list` の出力を変えられなくなる。関数は `commands/` に置き、TUI は機密の置き場を直接読まない。
値の平文を返さないため、TUI のモジュールが値を画面へ出す経路が構造として無い。

### 決定 5: 一覧は現物から読み、キャッシュへ落ちない

一覧は編集の入口である。キャッシュの値を見て編集すると、`set` の読み直し（`fresh`）とで内容が食い違い、
利用者が見た一覧とサーバの中身が違うまま操作することになる。届かないときは一覧を出さずに理由を出す。

### 決定 6: 範囲は「共通」と「プロジェクト」の 2 つで選び、プロジェクトのグループは選ばせない

`-p` はプロジェクトのグループの置き場だけを読み書きする（PLAN56 決定 6）。グループを別に選ばせると、
選べるのに保存で必ず失敗する組み合わせができる。共通だけがグループを選ぶ。グループの候補は
`$DEVBASE_ROOT/env` のグループと各プロジェクトのグループを置き場のグループ名で重複を除いたもので、
既定は `$DEVBASE_ROOT/env` のグループ。候補に無い名前は「名前を入力」で入れ、`--group` と同じ検証を通す。

### 決定 7: 接続先の既定値を持たず、TUI からは backend を切り替えない

#295 で devbasex は共通のサーバを運用しないと決まった。既定の接続先を置くと、知らないサーバへ
ブートストラップ機密を送る経路になる。接続先の欄は今の値を見出しに出すだけで、空なら変えない。
openbao でない端末で欄を出さないのは前提 8 のとおりで、切り替えは機密の移し替えと切り戻しを伴う。

### 決定 8: `secret_id` は `use` の属性として同じプロセスの中で渡す

TUI が `use` を呼ぶと、今の `_read_secret_id` は TTY を見て 2 度目の伏せ字入力を出す。TUI の欄で集めた値を
属性で渡せば入力は 1 度で済み、Esc の規約も TUI の欄に揃う。CLI の引数には足さないため、`argv` や
`ps` から値が見える経路は増えない。`--secret-id-stdin` へ流し込む形は、同じプロセスの `sys.stdin` を
差し替えることになり、TUI の入力と衝突するため採らない。

### 決定 9: token の直接入力は作らず、ブートストラップ機密を入れる欄にする

前提 1 のとおり、token をホストのディスクへ置かない既存の決定を守る。token の欄を作ると、保存しない
なら TUI を閉じるたびに入れ直しになり、保存するならこの決定を覆す。要るかどうかは依頼者が決める
（未確認のまま残ること）。

### 決定 10: 値の伏せ字は、キー名によらず全ての行に当てる

`list` の伏せ字はキー名の語（`KEY` / `TOKEN` など）で決まり、語を含まない機密は平文で出る。TUI の一覧は
画面に残り、画面共有や録画に写るため、受け入れ条件どおり全ての行を伏せる。長さも出さない。値を確かめる
経路は CLI の `env get` と `list --reveal` に残す。

### 決定 11: `sync --user` をファイルの backend で終了コード 2 にする

`set --user` はファイルの backend で 1 を返すが、`sync --user` は受け入れ条件どおり 2 にする。`sync` の
`--user` は宛先の既定を変える引数で、使えない組み合わせは引数の誤り（`--group` と同じ 2）として扱う。
`set` の終了コードは変えない（CLI の出力を変えないため）。

| `sync` でキーがどちらにも無いときの既定 | この設計は今と同じチーム共通（前提 4）。#268 の挙げる「静的キーがチーム全員の読める置き場へ入る」危険を理由に個人共通へ変えるかは依頼者が決める。変えるなら I2 の `--user` 無しの最後の分岐だけが変わる |
