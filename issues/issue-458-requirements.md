# #458: 既存の世代の名前で snapshot create --full を打つと、full.tar.zst が変更分だけになり復元でファイルを失う

正は課題の本文（#458）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

## 何を見つけたか

既にある世代の名前で `devbase snapshot create --name <名前> --full` を打つと、`full.tar.zst` が「前の控えからの変更分」だけのアーカイブになる。`_create_full` は世代のディレクトリにある `snapshot.snar` を消さずに `tar --listed-incremental=/backup/snapshot.snar` を打つため、GNU tar は差分（レベル 1）として控える。

`devbase-snapshot:latest` の GNU tar で、同じコマンドの形を使い確かめた（2026-10-12、作業用のディレクトリ。利用者のボリュームは使っていない）。

1. `ai/a`・`ai/b` を置き、`tar --listed-incremental=/backup/snapshot.snar -cf /backup/full.tar -C /source ai`
2. `ai/c` を足し、同じ snar のまま同じコマンドで `full.tar` を作り直す
3. `tar -tf /backup/full.tar` → `ai/` と `ai/c` だけ（`ai/a`・`ai/b` が無い）

あわせて、前からあった `incr-*.tar.zst` は消されずに残り、`meta.yml` の `files` だけが `[full.tar.zst]` に戻る（復元は `incr-*.tar.zst` を glob で拾うため、残った差分も適用される）。

## どこで見つけたか

`lib/devbase/snapshot/manager.py` の `create`（`is_new` が偽で `full=True` のとき）→ `_create_full` → `backup_command`。#368（スナップショットの除外）の設計で、除外を変えた後に利用者が既存の世代へ `--full` を打つ経路を調べていて見つけた。

## なぜこの変更の範囲外なのか

#368 の受け入れ条件は、除外の適用と、除外の一覧が違う世代へ差分を積まないこと（受け入れ条件 6・7）までで、既存の世代を `--full` で作り直す経路の振る舞いを含まない。対象範囲の「含まない」にある「復元の対象・順序・失敗時の案内の変更」「世代の保持・系列の規則の変更」にも当たらない別の不具合で、除外の有無に関わらず起きる。根拠: Value 2（MVV 版 1）

## 直さないと何が起きるか

既存の世代の名前で `--full` を打った後にその世代を復元すると、復元はボリュームを空にしてから `full.tar.zst` を展開するため、前の控えから変わっていないファイル（多くは会話の記録や設定）が復元後のボリュームに無い。利用者は「フルを取り直した」と思っているため、失ったことに復元の後まで気づかない。`--name` を省いた `create` と `devbase up` の自動スナップショット（新しい世代は新しいディレクトリ）では起きない。

## 起票者の推定

- 利用者が既存の世代の名前で `--full` を打つことがある（推した出所: `docs/user/cli-reference/05-snapshot.md` の `--name` と `--full` の説明が、既存の名前を禁じていない）
- 復元で変わっていないファイルを失う（推した出所: 上の手順 3 の中身の一覧と、`manager.py` の `restore` が `clear_command` の後に full を展開すること。復元までは実際に試していない）

## 目的

- 既存の世代の名前で `devbase snapshot create --name <名前> --full` を打ったとき、その世代が「打った時点のボリュームの
  全体（除外の一覧を除く）」を 1 本の `full.tar.zst` で持つ状態にし、復元でファイルを失わないようにする
- 作り直しに失敗しても、それまでの世代の控えを失わない（Value 2「作り直しで失わない」）

## 前提

- 前提 1: 既存の世代の名前で `--full` を打つ操作は禁じず、受け付けて世代を作り直す（止めて新しい名前を求める形は採らない。
  文書が「名前付きフルバックアップ」の例として `--name before-upgrade --full` を挙げ、同じ名前で取り直す使い方を禁じていないため）
- 前提 2: 作り直した世代は、前の `full.tar.zst`・`incr-*.tar.zst` の中身を引き継がない。作り直しが成功した後、
  その世代から前の時点へ戻す手段は無くなる（前の時点を残したい利用者は別の名前で作る。今の文書の範囲で読める）
- 前提 3: `snapshot.yml` のその世代の `created_at` は今の振る舞いのまま変えない（差分を積んだときと同じく `updated_at` と
  `incremental_count` だけを更新する）。系列の最新の世代とローテーションの順は `created_at` で決まるため、変えると
  別の課題の振る舞いが変わる
- 前提 4: CI の `pytest`（ubuntu の runner）には GNU tar と zstd があり、実の tar で走るテスト（`tests/snapshot/test_backup_real_tar.py`
  の形）が飛ばされずに走る。macOS の手元では飛ばされ得るため、実の tar の確かめは CI の結果か `devbase-snapshot:latest` の中で取る
- 前提 5: 「作り直しに失敗した」は、控えのコマンド（docker の中の tar・zstd）が失敗して `SnapshotError` になった場合を指す。
  ホストのプロセスが途中で殺された・電源が落ちた場合の中途の状態は、この課題では扱わない

## 対象範囲

含む:

- 既存の世代のディレクトリへ `full.tar.zst` を作る経路の振る舞い（`create --name <既存> --full`）。同じ関数を通る
  ほかの経路（`snapshot.snar` が無い世代への差分の指定が full へ切り替わる経路、同じ秒に重なった復元前バックアップ）も、
  作り直した世代に前の差分が残らない同じ規則に従う
- 作り直しの後の世代の `meta.yml`（`files`・`incremental_count`・`exclude`・`type`）と `snapshot.yml` のエントリの値
- 作り直しに失敗したときに、世代のファイルを作り直す前の状態に保つこと
- この振る舞いを利用者の文書（`docs/user/cli-reference/05-snapshot.md`・`docs/user/snapshot-guide.md`）と確定仕様
  （`docs/specifications/snapshot-series.md` か `snapshot-exclude.md`）に書くこと、`CHANGELOG.md` の `[Unreleased]`

含まない:

- 新しい名前の世代の作成（`--name` を省いた `create`、`devbase up` の自動スナップショット）。この不具合は起きておらず、振る舞いを変えない
- 既存の世代へ差分を積む経路（`--full` なしの名前の指定）の判定の規則（対象ボリューム → 控えの起点 → 除外の一覧）
- 復元の対象・順序・失敗時の案内、`--point` の意味
- 世代の保持・系列・ローテーションの規則、`created_at` の扱い（前提 3）
- すでに壊れた形で作り直された世代（`full.tar.zst` が差分で、前の `incr-*` が残る世代）を見つける・直す手段。
  壊れた世代の中身は控えた時点から戻せないため、検出と案内を足すかは未決 1 に置く
- `snapshot copy`・`delete` の振る舞い
- `devbase-snapshot` のイメージの中身（tar・zstd の版）の変更

## 受け入れ条件

- [ ] 1. 前提: 世代 `g` の `full.tar.zst` にファイル `a`・`b` があり、その後 `incr-001.tar.zst` が積まれている。ボリュームに `c` を足した
      操作: `create(name='g', full=True)`
      結果: `g/full.tar.zst` の中身の一覧（`tar -tf`）に `a`・`b`・`c` がすべて入る（実の GNU tar と zstd で確かめる）
- [ ] 2. 1 の後に `g` を復元すると、復元先のボリュームに `a`・`b`・`c` があり、`a`・`b` の中身は作り直した時点の中身と同じになる
      （作り直す前の `incr-001` で変わった中身が上書きで戻らない）
- [ ] 3. 1 の後、`g` のディレクトリに `incr-*.tar.zst` と `snapshot.snar.bak` が無く、`g/meta.yml` は `type: full`・`files: [full.tar.zst]`・
      `incremental_count: 0` になり、`exclude` は作り直した時点の除外の一覧になる
- [ ] 4. 1 の後、`snapshot.yml` の `g` のエントリは 1 件のままで、`incremental_count` が 0 になり、`created_at` は作り直す前と同じ値である
- [ ] 5. 前提: 世代 `g` に `full.tar.zst`・`incr-001.tar.zst`・`snapshot.snar`・`meta.yml` がある
      操作: `create(name='g', full=True)` の控えのコマンドが失敗する
      結果: `SnapshotError` になり（CLI は終了コード 1）、`g` の 4 つのファイルは作り直す前とバイト列が同じで、ほかのファイルが増えていない。
      `snapshot.yml` も変わらない
- [ ] 6. 新しい full の控えには成功し、前の差分アーカイブを除くのに失敗したとき、`create` は成功として返らない（`SnapshotError`、CLI は終了コード 1）
- [ ] 7. 1 の後に `create(name='g')`（`--full` なし）を打つと `g/incr-001.tar.zst` ができ、その中身は 1 の後に変えたファイルだけである
      （作り直した full から差分を積み直せる）
- [ ] 8. `snapshot.snar` の無い世代 `g`（`incr-*.tar.zst` を持つ）へ `create(name='g')` を打ち full へ切り替わったときも、3 と同じく
      前の `incr-*.tar.zst` が残らない
- [ ] 9. 退行しない: 新しい名前の世代の `create`（`--full` の有無とも）と `devbase up` の自動スナップショットのアーカイブ・`meta.yml`・
      `snapshot.yml` は今と同じになり、既存のテスト（`tests/snapshot/`・`tests/commands/`）がすべて通る
- [ ] 10. `docs/user/cli-reference/05-snapshot.md` と `docs/user/snapshot-guide.md` に「既にある世代の名前で `--full` を打つと、その世代を
      今のボリュームの全体で作り直し、前の差分は消える（前の時点へは戻せない）」ことが書かれている

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 可用性 | 作り直しに失敗しても、その世代は作り直す前と同じに復元できる（受け入れ条件 5） |
| 性能・拡張性 | 作り直しの間は、前の世代のファイルと新しい `full.tar.zst` が同時に `backups/<名前>/` にあり得る。一時に要るディスクは最大で「前の世代の大きさ + 新しい full の大きさ」で、これを超える置き場を足さない |
| 運用・保守性 | 作り直したことが INFO の 1 行で分かる（世代の名前と、除いた差分の本数を含む） |
