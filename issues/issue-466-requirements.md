# #466: 差分の作成が失敗すると snapshot.snar が進んだまま残り、次の差分が失敗の前の変更を含まず復元でファイルを失う

正は課題の本文（#466）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

## 何を見つけたか

既存の世代へ差分を積む `devbase snapshot create --name <名前>`（と `devbase up` の自動スナップショット）で、
控えのコマンドが失敗すると、`snapshot.snar` が失敗した回の状態まで進んだまま残る。

- `_create_incremental` は `cp snapshot.snar snapshot.snar.bak && tar --listed-incremental=/backup/snapshot.snar ... | zstd -o incr-NNN.tar.zst` を打つ。
  tar は zstd の成否に関わらず snar を書き換える
- 失敗すると `SnapshotError` になるが、`snapshot.snar.bak` から snar を戻す処理は無い。次の差分の作成で `cp` が進んだ snar を
  `.bak` へ上書きし、戻す手がかりも消える
- 次の差分は「失敗した回の時点」からの変更しか持たない。前の差分から失敗した回までに足した・変えたファイルは、どのアーカイブにも入らない

同じ形（tar が snar を進めた後に zstd が失敗する）を `devbase-snapshot:latest`（GNU tar 1.35・zstd 1.5.7）で確かめた（2026-10-12、
作業用のディレクトリ。利用者のボリュームは使っていない）。full を作った後に `ai/c` を足し、zstd が失敗する形で控えを打つと
snar が 76 → 80 バイトに進み、その後に積んだ差分の中身は `ai/` だけで `ai/c` が無かった（#458 の設計の実測。#458 は full の経路）。

あわせて、zstd が書き込みの途中で失敗した場合は作りかけの `incr-NNN.tar.zst` が世代に残り得る。番号は `incr-*` の本数から
決めるため次の差分は番号を進め、復元は残った作りかけを glob で拾って展開に失敗し得る（実機では確かめていない）。

## どこで見つけたか

`lib/devbase/snapshot/manager.py` の `_create_incremental`（`snapshot.snar.bak` を作る行と、失敗時に何も戻さないこと）。
#458（既存の世代へ `--full` を打つ経路）の設計で、同じ snar を進める形を調べていて見つけた。

## なぜこの変更の範囲外なのか

#458 の対象範囲は既存の世代のディレクトリへ `full.tar.zst` を作る経路で、「既存の世代へ差分を積む経路（`--full` なしの名前の指定）の
判定の規則」は含まない。#458 の受け入れ条件 5（失敗しても世代のファイルを保つ）は full の経路だけを縛り、差分の経路の失敗の
扱いは受け入れ条件に無い。範囲を広げると受け入れ条件が変わるため、承認ゲート 1 の前に足さない。根拠: Value 2（MVV 版 1）

## 直さないと何が起きるか

差分の作成が一度失敗した世代（ディスクの不足・docker の失敗など）では、その後の差分が失敗の前の変更を含まない。その世代を復元すると、
前の差分から失敗した回までに足した・変えたファイルが無いか古い中身になる。利用者は失敗の後に次の `devbase up` で差分が積めたのを見て
控えが続いていると思うため、復元するまで気づかない。`devbase up` の自動スナップショットは系列の最新の世代へ積むため、名前を指定しない
利用者にも起き得る。

## 目的

- 差分の作成（`devbase snapshot create --name <名前>` と `devbase up` の自動スナップショットが既存の世代へ積む経路）が失敗しても、
  その世代の控えの連なりが欠けないようにする。失敗の後に積んだ差分を含めて復元したとき、最後に成功した差分の時点から後の
  変更が復元先に入っている状態にする
- 失敗した回の作りかけのアーカイブが世代に残らず、復元がそれを拾って止まらないようにする
- 確定仕様の「運用」が既知の欠陥として書いている差分の経路の扱い（`snapshot-series.md` の #466 の行）を、守られる条件へ置き換える

## 実機で確かめたこと

2026-10-13、`devbase-snapshot:latest`（Id `b19bbbecb642`、作成 2026-09-30）を `docker run --rm` で、`/tmp` の作業用のディレクトリを
`/source:ro` と `/backup` に付けて打った。利用者のボリュームは使っていない。控えのコマンドは今の `_create_incremental` と同じ形
（`cp snapshot.snar snapshot.snar.bak && tar --listed-incremental=... | zstd -1 -T0 -o incr-NNN.tar.zst`）。

| # | 形 | 結果 |
| --- | --- | --- |
| R1 | full → `incr-001`（成功）→ 3MB のファイル `c` を足し、`incr-002` を zstd がファイルの大きさの上限で書く途中に失敗する形で打つ | `PIPESTATUS=141 153`。tar は SIGPIPE で止まり snar は進まなかった。102400 バイトの作りかけの `incr-002.tar.zst` が残った。docker の終了コードは 0（パイプの最後の終了コードを見ない形で打ったため。実装の経路では `SnapshotError` になる） |
| R2 | R1 の世代を full → `incr-001` → `incr-002` の順に展開する | `incr-002` で `zstd: premature end`・`tar: Unexpected EOF in archive`、`PIPESTATUS=1 2`。復元はこのアーカイブで止まる |
| R3 | R1 の作りかけを消し、ファイル `e` を足して、zstd がすぐ失敗する形（出力の名前が既にある）で差分を打つ | `PIPESTATUS=0 1`。tar は小さいデータをパイプへ書き終え、snar が 78 → 84 バイトに進んだ。`.bak` は前の snar のまま |
| R4 | R3 の後に次の差分を打ち、中身を一覧する | 中身は `ai/` だけで `ai/e` が無い。起票者の推定 S1 を差分の後の失敗でも確かめた |
| R5 | 存在しないメンバーを渡し、tar が致命的に失敗する形で打つ | `PIPESTATUS=2 0`、パイプ全体の終了コードは 0。今の差分の経路は、tar の失敗を成功として扱う |

R5 の形は、今の控えのコマンドではメンバーがマウント先（必ずある）なので起きにくい。ただし tar が読み取りで止まったアーカイブは
R2 と同じく復元を止め得るため、「失敗」の定義に含める（前提 1）。

## 前提

- 前提 1: 差分の作成の「失敗」は、世代の作り直しの控えのコマンドと同じ定義にする。tar の終了コードが 2 以上、または zstd の
  終了コードが 0 以外。tar の 1（読む間にファイルが変わった）は今と同じく通す。`devbase-snapshot` は root で読み取り専用の
  マウントを読むため、利用者のボリュームで tar が 2 以上を返すのは読み取りの致命的な失敗だけである、と置く。外れて自動
  スナップショットの差分が毎回失敗する形が見つかったら、設計か実装でこの前提を見直す
- 前提 2: 差分の作成が失敗したときの利用者から見える扱い（`create` は `SnapshotError` で終了コード 1、`devbase up` は警告 1 行で
  起動を続ける）は今と同じにする。失敗の代わりに full へ切り替える・新しい世代を作るといった振る舞いは足さない
- 前提 3: 世代の作り直しの経路（`_create_full`・`_install_rebuilt_full`・`_discard_rebuild_temps`）と、新しい世代へ直接控える
  full の経路の控えのコマンドは変えない。新しい世代への full で tar の失敗を zstd の成功が隠し得ることは、この課題では扱わない
  （失敗しても前の控えは無く、消える前のファイルが無いため）
- 前提 4: 世代のファイルの形（`full.tar.zst`・`incr-NNN.tar.zst`・`snapshot.snar`・`meta.yml`）と `snapshot.yml` の形は変えない。
  差分の作成の途中だけに使う仮の名前のファイルを足してよいが、その名前は `incr-*.tar.zst` の glob・`is_archive_file`・
  `_has_previous_files` のどれにも当たらない形にする
- 前提 5: 実機の確かめは `devbase-snapshot:latest` の `docker run --rm` と作業用のディレクトリで行う。`devbase up` は
  作業用のプロジェクトでも打たない（利用者のボリュームが付く。AGENTS.md の落とし穴・P3）。ボリュームを丸ごと写さない

## 対象範囲

含む:

- `_create_incremental` の、snar の検査（組・控えの起点・除外の一覧・snar の有無）を通った後の控えから `meta.yml` の更新まで
- 差分の控えのコマンドの失敗の定義（前提 1）
- 失敗したとき・途中で止まったときに、`snapshot.snar` を打つ前の状態に保つ（または戻す）ことと、作りかけの差分を残さないこと
- 前の中断で残った差分の作成の仮の名前のファイルを、次の差分の作成の前に消すこと
- `docs/specifications/snapshot-series.md` の差分の経路に関わる記述（「運用」の #466 の行・「エラー処理」・「テスト観点」）と `CHANGELOG.md`

含まない:

- 世代の作り直し（`_create_full` の前のファイルがある経路）・新しい世代への full の控えのコマンド（前提 3）
- 復元前バックアップの名前の重なり（#473）。`_backup_before_restore` と確定仕様の「世代の作り直し」の場面の表の
  復元前バックアップの行・その下の段落・用語の表の「復元前バックアップ」は #473 が触る
- この変更より前の devbase で失敗した差分の作成が残した世代（snar が進んだ世代・作りかけの `incr-NNN.tar.zst` を持つ世代）を
  見つける処理や直す処理。ファイルの形から見分けられないため持たない。案内だけを書く（受け入れ条件 10）
- 復元（`restore`・`_apply_incrementals`）の振る舞い。作りかけを拾わない形は、作成の側で作りかけを残さないことで満たす
- `meta.yml` と `snapshot.yml` の書き込みの失敗の扱い（差分のアーカイブと snar が揃った後の失敗。今の扱いのまま）
- `snapshot.snar.bak` を読む処理を足すこと（作り続けるかは設計で決める。未決 1）

      （tar が 2 以上・zstd が 0 以外のそれぞれ）。結果: `SnapshotError` になり、世代の `snapshot.snar` は打つ前とバイト列が同じで、

      `incr-(N+1).tar.zst` も仮の名前のファイルも残らない。`snapshot.yml` も変わらない
- [ ] 2. 1 の失敗の後、ファイルを足して同じ世代へ次の差分を作ると、その差分は `incr-(N+1).tar.zst` の番号で作られ、中身に
      失敗した回より前に足したファイルと後に足したファイルの両方を含む（実測 R3・R4 の形が直っている）
- [ ] 3. tar が 1（読む間にファイルが変わった）・zstd が 0 の差分は今と同じく成功として扱い、`incr-(N+1).tar.zst` と進んだ snar を残す
- [ ] 4. 差分の作成が、控えが終わった後の各段（差分を世代へ置く・snar を進める）で例外で止まっても、世代は次のどれかの状態で残る。

| 大項目 | 条件 |

| 性能・拡張性 | 差分の作成で写すのは `snapshot.snar`（KB の桁）だけで、full と差分のアーカイブを写さない。世代のディレクトリが一時に使うディスクは今と同じ（差分 1 本分） |
| 移行性 | 世代と `snapshot.yml` の形は変えない（前提 4）。この変更の前の devbase へ戻しても、この変更の後に作った世代を読める。仮の名前のファイルが残っていても、前の devbase の glob に当たらない |
| 運用・保守性 | 失敗は `SnapshotError` の文言（`Dockerでのtar操作に失敗しました: {stderr}` の形）で、tar と zstd のどちらで止まったかを stderr から読める |

## 影響

| 対象 | 影響 |
| --- | --- |
| 公開インタフェース | 変わらない（CLI の引数・出力・終了コードは今と同じ） |
| データ | 形は変わらない。差分の作成の途中だけ仮の名前のファイルが世代に現れ得る |
| 既存の振る舞い | 差分の作成で tar が 2 以上を返すと、これまで成功だったものが失敗になる（前提 1）。失敗の後の世代の状態が変わる（snar を戻し、作りかけを消す） |
