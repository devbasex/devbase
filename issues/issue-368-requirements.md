# #368: スナップショットが作り直せるキャッシュ・一時ファイル・ログまで控える（除外の仕組みが無い）

正は課題の本文（#368）で、この文書はその写しである。`spec-copy.py write` で作り直す。手で直さない。

## 何を見つけたか

スナップショット（`devbase snapshot`）は、対象のボリューム（共通 `devbase_home_ubuntu` とグループのボリューム）を丸ごと控え、除外の仕組みを持たない（`lib/devbase/snapshot/manager.py` の `backup_command` は `tar --listed-incremental=... -cf - -C /source <各マウント先>` だけで、除外の指定が無い）。作り直せるキャッシュ・一時ファイル・ログも毎回控えている。

手元のボリュームで測った内訳のうち、控えなくてよいもの:

| パス（ボリューム内） | 大きさ | 中身 | 外してよい理由 |
| --- | --- | --- | --- |
| `.gemini/tmp/<プロジェクト>/` の `chats/` **以外**（`logs.json`・`logs/` など。共通・グループの両方） | 共通側で約 325MB（2026-10-02） | Gemini の作業用のログ・一時ファイル | 一時ファイル・ログ。ただし `chats/` 以外に復元で要るものが無いかは未確認 |
| `.codex/logs_2.sqlite`（共通） | 602MB | Codex の動作ログ（`logs` テーブルだけ。直近約 9.5 日分で古い行から消える） | 会話の履歴は `sessions/`・`thread_history_1.sqlite`・`state_5.sqlite` にある。使う間ずっと書き換わるため、差分のたびにファイル全体が入る |
| `.codex/.tmp`・`.codex/cache`（共通） | 約 200MB | 一時ファイル・キャッシュ | 作り直せる |
| `.claude/plugins/cache`・`.claude/plugins/marketplaces`（共通） | 約 607MB・約 70MB | プラグインとマーケットプレイスの取得物 | 配布元から取り直せる |
| `.serena/logs`（共通） | 158MB | 日付ごとのログ（消されず溜まる） | 復元で要らない |

外さないもの:

- 会話の記録（`.claude/projects`・`.codex/sessions`・`thread_history_1.sqlite`・`state_5.sqlite`・**`.gemini/tmp/<プロジェクト>/chats/`**）。`.gemini/tmp` は名前に反して Gemini の会話の記録（`chats/session-*.jsonl`）を持つ。共通側の `.gemini/tmp` 約 1.3GB のうち約 984MB が `chats/` である（2026-10-02）。`.gemini/tmp` を丸ごと外すと会話の記録を失う
- `.claude/plugins` の状態のファイル（`installed_plugins.json`・`known_marketplaces.json`・`data/`）。入れたプラグインとマーケットプレイスの一覧と、プラグインが持つデータで、取り直せない
- `.serena/language_servers` — 取り直しは TLS を傍受するプロキシの下で失敗しやすく、手で差し替えた版（`*.bak-*`）がある。変わらないため差分への負担は小さい

## 決めること

- 除外の一覧を持つ場所（既定の一覧を本体に持つか、利用者が足せるか）
- 除外の単位。`.gemini/tmp` と `.claude/plugins` は、ディレクトリ丸ごとではなく中の一部だけを外す必要がある
- 復元したときに除外したパスが無い状態で、各 CLI が起動できること（`logs_2.sqlite` は `_sqlx_migrations` を持つので作り直すと見ているが未確認。`.claude/plugins/cache` が無いときにプラグインを取り直すか）
- 世代の途中で除外を変えたときの扱い。差分は GNU tar の `--listed-incremental` で作っており、前の世代に入っていたパスを次の差分で除外すると、そのパスは消えたものとして記録される。差分を順に展開する復元（`--listed-incremental=/dev/null`）では、そのパスが消える。除外を足すときは新しいフルから始めるなどの扱いが要る

## 関連

差分バックアップが毎回全体を控えていた不具合（tar の起点の修正、PR #369 でマージ済み）とは別。そちらの修正で変わらないファイルは差分に入らないため、この課題の効果は主に「頻繁に書き換わるもの」とフルバックアップの大きさに出る。

## 目的

- スナップショットが、作り直せるもの（一時ファイル・ログ・取り直せる取得物）を控えずに済むようにし、フルの世代と頻繁に書き換わるファイルの差分の大きさを減らす
- 会話の記録・入れたプラグインの一覧・利用者が手で整えたものは、これまでどおり控え、復元で戻る

## 前提

- 前提 1: 対象は devbase のスナップショット（`devbase snapshot create`・`devbase up` の自動スナップショット・`restore` の前に作る復元前バックアップ）が作るアーカイブである。`snapshot copy` は既存の世代のアーカイブを写すだけで、除外を新たに適用しない
- 前提 2: 既定の除外の一覧は、課題の本文の「控えなくてよいもの」の表（S1〜S5）から作る。利用者の決定（2026-10-11）に従う。表のパスが端末に無いときは、そのパスを除外しても何も起きない
- 前提 3: `.gemini/tmp/<プロジェクト>/` の `chats/` 以外に、Gemini の復元で要るものは無い。誤っていたら、そのパスを既定の除外の一覧から外す形で直せる（局所的に直せる）
- 前提 4: 除外したパスが無い状態から、Claude Code・Codex・Gemini CLI・Serena は起動でき、要るものを作り直すか取り直す。成否はマージの前に受け入れ条件 9 で確かめ、起動できない CLI があれば、そのパスを既定の除外の一覧から外す
- 前提 5: 利用者が足す除外は、ボリュームの中の相対のパス（とその下）で書く。書き方（パターンの記法・置き場）は設計で決める
- 前提 6: 除外の一覧が変わったことで、更新後の最初の自動スナップショットが系列ごとに新しいフルの世代を作ってよい（1 系列につき 1 回のフルの取り直し）。既存の世代のアーカイブは書き換えない

## 対象範囲

含む:

- 既定の除外の一覧を本体に持ち、作成（フル・差分）と復元前バックアップのアーカイブへ適用すること
- 利用者が設定で除外を足せること
- 除外の一覧が前の控えと違うときに、復元で除外の外のデータを失わない扱い
- 除外したパスが無い状態で復元した後に、各 CLI が起動できることの確認
- 利用者向けの文書（スナップショットガイド・CLI リファレンス・設定の文書）と `CHANGELOG.md` の `[Unreleased]`

含まない:

- 既定の除外の一覧から利用者が項目を外すこと（利用者の決定は「足せる」だけである）
- 既にある世代のアーカイブから除外のパスを取り除くこと（作り直さない）
- 復元の対象・順序・失敗時の案内の変更（除外したパスが復元後に無いことを除く）
- 世代の保持（ローテーション）・系列・最小間隔の規則の変更
- 各 CLI のログやキャッシュの置き場・保存の期間を変えること（CLI 側の設定）
- `snapshot copy` で除外を適用し直すこと
- base イメージに入れる道具の変更（P1 に当たる変更はしない）

## 受け入れ条件

- [ ] 1. 前提: 共通ボリュームとグループのボリュームに、既定の除外のパス（`.gemini/tmp/<プロジェクト>/logs.json`・`.gemini/tmp/<プロジェクト>/logs/`・`.codex/logs_2.sqlite`・`.codex/.tmp`・`.codex/cache`・`.claude/plugins/cache`・`.claude/plugins/marketplaces`・`.serena/logs`）がある。操作: `devbase snapshot create --full` で世代を作る。結果: `full.tar.zst` の中身の一覧（`tar -t`）に、どのパスもその下のファイルも無い
- [ ] 2. 同じ世代の `full.tar.zst` の中身の一覧に、`.claude/projects`・`.codex/sessions`・`.codex/thread_history_1.sqlite`・`.codex/state_5.sqlite`・`.gemini/tmp/<プロジェクト>/chats/` の下のファイル・`.claude/plugins/installed_plugins.json`・`.claude/plugins/known_marketplaces.json`・`.claude/plugins/data/`・`.serena/language_servers` がある（置いたパスのとき）
- [ ] 3. 差分（`incr-NNN.tar.zst`）でも同じ除外が効き、前の控えから書き換えた `.codex/logs_2.sqlite` が差分の中身の一覧に無い
- [ ] 4. 復元前バックアップ（`pre-restore-*`）のアーカイブにも同じ除外が効く
- [ ] 5. 利用者が設定で除外を 1 つ足すと、次に作る世代のアーカイブの中身の一覧にそのパスとその下が無く、既定の除外も引き続き効いている
- [ ] 6. 前提: 系列の最新の世代が、今と違う除外の一覧で作られている（この変更より前に作った、除外を持たない世代を含む）。操作: `devbase up` の自動スナップショット。結果: その世代へ差分を積まず、系列に新しい世代を作り、その理由をログの 1 行で示す
- [ ] 7. 前提: 名前を指定して、今と違う除外の一覧で作った世代へ差分を作ろうとする。結果: 差分を作らず、理由を示して止まる（終了コード 1）。その世代のアーカイブと `snapshot.snar` は変わらない
- [ ] 8. 除外を適用した世代を復元すると、除外の外のパスは控えた時点の中身に戻り、除外したパスは復元後のボリュームに無い（復元の前にボリュームを空にするため）
- [ ] 9. 前提: 既定の除外のパスを消したホームで dev コンテナを起動する。操作: Claude Code・Codex・Gemini CLI・Serena をそれぞれ起動する。結果: どれもエラーで止まらずに起動し、Claude Code は入れたプラグインの一覧（`installed_plugins.json`）のプラグインを使える状態になる
- [ ] 10. この変更より前に作った世代（除外を持たない世代）を、変更後の devbase で一覧・復元でき、復元の結果は変更前の devbase で復元したときと同じである
- [ ] 11. 利用者の除外に、ボリュームの外を指す値（絶対パス・`..` の要素を含む）や空の値を書くと、その値を採らずに警告を 1 行出し、残りの除外の一覧で控えを作る
- [ ] 12. 利用者の除外を書いていないときは、既定の除外だけで控えを作り、警告を出さない
- [ ] 13. 除外のパスが端末に無いとき（その CLI を使っていない）、控えの作成は失敗せず、警告も出さない
- [ ] 14. 世代ごとに、作ったときの除外の一覧が後から読める（世代のメタ情報に残る）

## 非機能の条件

| 大項目 | 条件 |
| --- | --- |
| 性能・拡張性 | 課題の本文の測定（2026-10-02）と同じ構成で、フルの世代の展開前の控えの対象から、既定の除外のパスの合計（約 1.9GB）が減る。測った端末とボリュームの大きさを記録に残す |
| 運用・保守性 | 除外の一覧が前の控えと違うために新しい世代を作るときは、理由をログの 1 行で示す（受け入れ条件 6）。世代ごとの除外の一覧が後から読める（受け入れ条件 14） |
| 移行性 | 既存の世代は書き換えずにそのまま一覧・復元できる（受け入れ条件 10）。更新後の最初の自動スナップショットで、系列ごとに新しいフルの世代を作る（前提 6）。切り戻し（変更前の devbase へ戻す）で、変更後に作った世代を復元すると除外したパスは無い |
