## Mission

開発者と AI エージェントが、どのプロジェクトでも、すぐに整った開発環境で作業を始められるようにする。

## Vision

誰がどの端末で立ち上げても同じ開発環境が再現でき、壊しても作り直せる、プロジェクトの開発環境の基盤になる。

## Value

1. **入った時点で使える**: よく使う道具は base に入れ、版を固定する。ただし base を重くしすぎず、重い道具は派生イメージに置く。
2. **作り直しで失わない**: 利用者やツールが足した設定の置き場を用意し、作り直しでも残す。
3. **プロジェクトの境界を守る**: プロジェクトごとの設定・機密・データを分け、確認なしに持ち込まない。

## 必ず人の承認が要る操作

| # | 操作 | 理由 |
| --- | --- | --- |
| P1 | base イメージに入れる道具や、その版を変える | すべての派生イメージと利用者の建て直しに影響し、アーキテクチャごとの差も出るため |
| P2 | タグ・GitHub Release を作る | 版の区切りを公開の配布物として確定させ、後から取り消しても見た人は戻らないため |
| P3 | 実際の利用者の環境で `devbase up` を実行する | 動いているコンテナとサービスを作り直し、利用者の作業を止め得るため（`scale` と `login` は含めない） |

## 補足

main へのマージは利用者への配布になるが、必ず人の承認が要る操作には含めない。マージは NDF の共通原則とこの MVV に照らした判断で進め、版の確定（P2）で人が確かめる。
